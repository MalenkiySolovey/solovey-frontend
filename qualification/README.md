# Producer qualification policy

inputs.json is a reviewed admission of a generated immutable Product projection, not another component source lock. Product components/sources.lock.json remains authoritative. The input archive lives at an exact Product Git commit; the separately admitted archive and manifest SHA256 values are checked before compilation. No component UI source archive is tracked in this repository. Historical Panel Update inputs are accepted only by the compatibility validator; current maintenance UI is built in here.

The producer emits solovey.frontend-distribution/v1 provenance with exact source commit/tree, version, source-archive hash, Node/npm/lock identity, profile and selected ComponentIDs, trusted input digest, Vite manifest digest, archive digest and every packaged file hash/size. Binary file maps are canonical gzip JSON with regular paths only. LICENSE, NOTICE and third-party dependency metadata/runtime notices accompany each distribution. Full, Core, minimal, empty Core and three accepted custom component selections are qualified.

Frontend CI is read-only, uses immutable action revisions, checks exact PR head commits, and requires producer-linux, producer-windows, artifact-parity and backend-browser. The browser job pins the Product fixture at an exact commit and verifies its Backend revision against inputs.json before embedding the new distribution. The fixture retains its own accepted Frontend pin for Product tooling, so the producer does not depend on completing its own Product cutover. Independent build jobs receive no Product checkout. Browser retries are zero. New distributions require a new immutable version and qualified source; published tags/assets must never be moved/replaced. Product signed release authority remains unchanged.
